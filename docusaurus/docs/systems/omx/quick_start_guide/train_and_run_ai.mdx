<GuidePage guide={quickStart} title="Train and run AI">

You show OMX a task about 50 times with the leader arm. The PC learns from your tries, and then OMX tries the task by itself. This is imitation learning, done once with Cyclo Intelligence. For every option, see [Cyclo Intelligence](../imitation_learning/imitation_learning.mdx).

Start after [Move OMX](./move_omx.mdx). This page also needs an NVIDIA graphics card.

## 1. Get the graphics card ready \{#get-the-graphics-card-ready}

The AI model learns and runs on the NVIDIA graphics card. Get it ready before you install Cyclo Intelligence. Check what your PC has first, then install only what is missing.

### Do this

#### A. Check what is there

<Terminal>

```bash
nvidia-smi
docker info | grep -i runtimes
```

</Terminal>

<Terminal
  kind="output"
  checks={{1: 'Your NVIDIA card', 2: 'nvidia is in the list'}}
  note="Only the lines to look at are shown, and only the left part of the card's line. Your words and numbers can be different. That is fine."
>

```text
|   0  NVIDIA GeForce RTX 4090        Off |
 Runtimes: runc io.containerd.runc.v2 nvidia
```

</Terminal>

Both lines like this? Go to [Install Cyclo Intelligence](#install-cyclo-intelligence). If not, do only the parts below that you need.

#### B. Install the graphics driver

Do this if `nvidia-smi` says `not found` or `failed`. Use these steps from [Ubuntu's guide](https://documentation.ubuntu.com/server/how-to/graphics/install-nvidia-drivers/), not the command the terminal suggests. First bring Ubuntu up to date.

<Terminal>

```bash
sudo apt update && sudo apt upgrade
```

</Terminal>

If it asks `Do you want to continue? [Y/n]`, press **Enter**. Restart the PC. Then install the driver that fits your card.

<Terminal>

```bash
sudo ubuntu-drivers install
```

</Terminal>

Restart the PC again. Then do part A again.

#### C. Let Docker use the card

Do this if `nvidia` is not in the `Runtimes` line. It installs the NVIDIA Container Toolkit with the commands of [NVIDIA's guide](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html). Paste one block at a time, and wait until you can type again.

<Terminal>

```bash
sudo apt-get update && sudo apt-get install -y --no-install-recommends \
   ca-certificates \
   curl \
   gnupg2
```

</Terminal>

<Terminal>

```bash
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg \
  && curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
    sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
    sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
```

</Terminal>

<Terminal>

```bash
sudo apt-get update
sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
```

</Terminal>

Then do part A again.

### You should see

<Checks>

- Part A shows your card, and `nvidia` in the `Runtimes` line

</Checks>

<NotGood>

| You see | Do this |
| --- | --- |
| `NVIDIA-SMI has failed` after part B | Restart the PC once more. If it stays, see [Ubuntu's guide](https://documentation.ubuntu.com/server/how-to/graphics/install-nvidia-drivers/). |
| `permission denied`, or no `Runtimes` line | Docker does not run without sudo yet. Do part D of [Install Docker and Git](./move_omx.mdx#install-docker-and-git). |
| `Could not get lock` | Ubuntu is updating itself. Wait a few minutes, then paste the same lines again. |

</NotGood>

<details>
  <summary>How does it work?</summary>

  The graphics driver lets Ubuntu use the card. The NVIDIA Container Toolkit lets the programs inside Docker use it too. Cyclo Intelligence and the AI program run in Docker, so they need both.

  These are the checks of [Cyclo Intelligence Setup](../imitation_learning/setup.mdx#requirements). Parts B and C are copied from Ubuntu's and NVIDIA's guides. If they change their commands, their pages linked above have the new ones.

</details>

## 2. Install Cyclo Intelligence \{#install-cyclo-intelligence}

Cyclo Intelligence records what you show OMX, and later runs the AI model. You install it once.

### Do this

#### A. Install

<Terminal>

```bash
curl -fsSL https://raw.githubusercontent.com/ROBOTIS-GIT/cyclo_intelligence/main/install.sh | bash
```

</Terminal>

#### B. Start it and enter its container

<Terminal>

```bash
cd ~/cyclo_intelligence
./docker/container.sh start
./docker/container.sh enter
```

</Terminal>

It downloads Cyclo Intelligence, then opens a terminal inside its container. Wait until you can type again. If it asks for your password, type it.

#### C. Check the Zenoh setting

<Terminal where="Cyclo container">

```bash
grep ZENOH_CONFIG_OVERRIDE ~/.bashrc
```

</Terminal>

### You should see

<Terminal
  kind="output"
  where="Cyclo container"
  checks={{1: 'The setting is there'}}
  note="The second line starts with # and does nothing. That is fine."
>

```text
export ZENOH_CONFIG_OVERRIDE='transport/shared_memory/enabled=true'
# export ZENOH_CONFIG_OVERRIDE='transport/shared_memory/enabled=true;mode="client";connect/endpoints=["tcp/192.168.60.139:7447"]'
```

</Terminal>

Then type `exit` and press **Enter** to leave the container.

<NotGood>

| You see | Do this |
| --- | --- |
| `curl: command not found` | Paste `sudo apt install curl`, then do part A again. |
| `Refusing to modify an existing Cyclo checkout` | It was downloaded before. Update it instead: paste `cd ~/cyclo_intelligence && git pull && git submodule update --init --recursive`. Then do part B. |
| `no space left on device` | Free some disk space. Then do part B again. |
| No line in part C | Paste <code>echo "export ZENOH_CONFIG_OVERRIDE='transport/shared_memory/enabled=true'" >> ~/.bashrc</code>, then `source ~/.bashrc`. |

</NotGood>

<details>
  <summary>How does it work?</summary>

  Cyclo Intelligence runs in its own Docker container, next to the robot software. You use it through a web page, which opens in the next step.

  The Zenoh setting lets Cyclo Intelligence talk to the robot's programs on this PC. The container comes with it, and part C only checks it.

  These are the steps of [Cyclo Intelligence Setup](../imitation_learning/setup.mdx). For all its options, see that page.

</details>

Everything from [Check what OMX sees](#check-what-omx-sees) must still be running: four terminals and the **Record** page.

#### D. Train

In the same terminal, enter the AI program's container.

<Terminal>

```bash
./docker/container.sh enter-lerobot
```

</Terminal>

Then paste the training command. You do not need to change anything in it.

<Terminal where="AI program container">

```bash
lerobot-train \
  --dataset.repo_id=local/pick_box \
  --dataset.root=/workspace/lerobot/Task_1_pick_box_MCAP_lerobot_v30 \
  --policy.type=act \
  --policy.chunk_size=50 \
  --policy.n_action_steps=50 \
  --policy.device=cuda \
  --policy.push_to_hub=false \
  --wandb.enable=false \
  --batch_size=8 \
  --steps=60000 \
  --save_freq=20000 \
  --output_dir=/workspace/model/lerobot/act_pick_box \
  --job_name=act_pick_box
```

</Terminal>

Lines with `step:` go by while it learns. Wait until it ends. How long it takes depends on your graphics card.

<NotGood>

<details>
  <summary>How does it work?</summary>

  The model is named ACT. It looks at the camera picture and the arm's angles, and learns which moves you made next. It goes through your tries many times: 60,000 small learning steps.

  The result is saved in `~/cyclo_intelligence/docker/workspace/model/lerobot/act_pick_box`. For other models and settings, see the [Model Training Guide](../imitation_learning/model_training.mdx).

</details>

<details>
  <summary>How does it work?</summary>

  Many times a second, the model looks at the camera picture and the arm's angles, and plans the next few seconds of moves. With **3D Sim Deploy**, the plan only shows in the 3D picture. With **Real Robot Deploy**, it goes to the motors.

  The model has no "done" signal. It keeps going until you click **Stop**. For every setting on this page, see [Model Inference](../imitation_learning/model_inference.mdx).

</details>

## If it does not work well \{#if-it-does-not-work-well}

With only one small camera on the wrist, a first model often does not do the task well. That is expected. The camera sees only what is in front of the gripper, and LeRobot, which trains the model in this guide, suggests two camera views.

To make it work better, check the usual reasons below. They come from the [LeRobot guide](https://huggingface.co/docs/lerobot/en/il_robots#tips-for-gathering-data) and its list of [what makes a good dataset](https://huggingface.co/blog/lerobot-datasets#what-makes-a-good-dataset). Then learn more in the Cyclo Intelligence manual, linked at the end.

| What went wrong | What to do |
| --- | --- |
| The camera cannot see the box | You should be able to do the task by only looking at the camera picture. With one camera on the wrist, the box must be in its picture from the start. |
| The scene changed after you recorded | Run OMX in the same place and light as when you recorded. Daylight from a window changes during the day. |
| Something else moved in the picture | Only the follower and the box should move in the picture. Keep hands, people and the leader arm out of it. |
| Your tries were not alike | Start every try from the same pose, and grasp the box the same way. Discard odd tries. |
| Too many spots for your tries | Keep about 10 tries at each spot. Add spots only after it works well. |
| The camera shakes | Fix the camera firmly. |
