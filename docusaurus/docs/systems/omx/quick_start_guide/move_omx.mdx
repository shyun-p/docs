You need an assembled OMX with its camera, and a PC with Ubuntu. The last page, [Train and run AI](./train_and_run_ai.mdx), also needs an NVIDIA graphics card.

## 1. Install Docker and Git \{#install-docker-and-git}

The robot software runs in Docker, and Git downloads it. Check what your PC has first, then install only what is missing.

### Do this

#### A. Check what is there

Open a terminal with **Ctrl + Alt + T**.

<Terminal hint>

```bash
docker compose version
git --version
docker run hello-world
```

</Terminal>

<Terminal
  kind="output"
  checks={{1: 'Docker', 2: 'Git', 3: 'Docker runs without sudo'}}
  note="Only the lines to look at are shown. Your version numbers can be different. That is fine."
>

```text
Docker Compose version v5.3.0
git version 2.43.0
Hello from Docker!
```

</Terminal>

All three lines like this? Go to [Connect OMX](#connect-omx). If not, do only the parts below that you need.

#### B. Install Git

Do this if the `git` line says `not found`. When it asks for your password, type it and press **Enter**. Nothing shows while you type.

<Terminal>

```bash
sudo apt update
sudo apt install git
```

</Terminal>

#### C. Install Docker

Do this if the first line says `not found`. Use these commands from [Docker's guide](https://docs.docker.com/engine/install/ubuntu/#install-using-the-repository), not the one the terminal suggests. Paste the first block and wait until you can type again. Then paste the second.

<Terminal>

```bash
# Add Docker's official GPG key:
sudo apt update
sudo apt install ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Add the repository to Apt sources:
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

sudo apt update
```

</Terminal>

<Terminal>

```bash
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

</Terminal>

If it asks `Do you want to continue? [Y/n]`, press **Enter**. Then do part D.

#### D. Use Docker without sudo

Do this after part C, or if the last line of part A says `permission denied`. It is a step of [Docker's guide](https://docs.docker.com/engine/install/linux-postinstall/#manage-docker-as-a-non-root-user).

<Terminal>

```bash
sudo usermod -aG docker $USER
```

</Terminal>

Log out of Ubuntu and log in again. Then open a terminal and do part A again.

### You should see

<Checks>

- Part A shows all three lines: Docker, Git, and `Hello from Docker!`

</Checks>

<NotGood>

| You see | Do this |
| --- | --- |
| `Could not get lock` | Ubuntu is updating itself. Wait a few minutes, then paste the same lines again. |
| `Unable to locate package docker-ce` | The first block of part C did not finish. Paste it again, then the second. |
| `'compose' is not a docker command` | An older Docker from Ubuntu is on the PC. Remove it with the command under "Uninstall old versions" in [Docker's guide](https://docs.docker.com/engine/install/ubuntu/#uninstall-old-versions). Then do parts C and D. |
| `permission denied` after part D | Restart the PC. Then do part A again. |

</NotGood>

<details>
  <summary>How does it work?</summary>

  Docker runs programs in containers. A container holds a program together with everything that program needs. So the robot software runs on its own Ubuntu 24.04 inside its container, whatever Ubuntu your PC has.

  Git downloads the robot software in [Install the software](#install-the-software). The last thing OMX needs from the PC is USB access, and you check it in [Connect OMX](#connect-omx).

  These are the requirements of [ROS 2 Setup](./setup_guide/ros2_setup.mdx). Parts C and D are copied from Docker's guide. If Docker changes its commands, its pages linked above have the new ones.

</details>

<NotGood>

| You see | Do this |
| --- | --- |
| Only one `OpenRB-150` line | Most often the follower's 12 V power is off. Check the adapter at the wall and at the follower. |
| No `OpenRB-150` line, or `No such file or directory` | Push both USB cables in fully, at the arm and at the PC. Use the cables from the OMX box. |
| No `Camera` line | Unplug the camera's USB cable and plug it in again. If that does not help, try another USB port. |
| A line is missing and its cable goes through a USB hub | Plug that cable straight into the PC. |

</NotGood>

<details>
  <summary>How does it work?</summary>

  The leader takes its power from the USB cable. The follower's motors need more power, so the follower has its own 12 V adapter. The PC can see the follower only while that power is on.

  The PC talks to each arm through a small board named OpenRB-150. That is the name you see in the terminal. For more, see [ROS 2 Setup](./setup_guide/ros2_setup.mdx).

  For the wiring of OMX-F, OMX-L and OMX-AI, see the [Setup Guide](./setup_guide/setup_guide.mdx).

</details>

## 3. Install the software \{#install-the-software}

Put the robot software on your PC and tell it which arm is which. You do this once.

### Do this

#### A. Download the robot software

<Terminal>

```bash
cd $HOME
git clone https://github.com/ROBOTIS-GIT/open_manipulator
cd $HOME/open_manipulator/docker
./container.sh start
```

</Terminal>

It asks for your password, then downloads the robot software. Wait until you can type again.

#### B. Enter the robot container

<Terminal>

```bash
cd $HOME/open_manipulator/docker
./container.sh enter
```

</Terminal>

<Terminal kind="output" where="Robot container" checks={{1: 'You are in the container'}} note="Your PC's name is different. That is fine.">

```text
root@my-pc:~/ros2_ws#
```

</Terminal>

Use this terminal for parts C and D.

#### C. The leader's port

Unplug the follower's USB cable from the PC. Only the leader's USB cable stays in. Then check the OpenRB serial ID.

<Terminal where="Robot container">

```bash
ls -al /dev/serial/by-id/
```

</Terminal>

<TutorialMedia
  label="The terminal lists one board, the leader's. Its name, which starts with usb-ROBOTIS_OpenRB-150 and ends with -if00, is marked in red."
  src="/img/systems/omx/quick_start_guide/setup_guide/physical_ai_tools/setup_port_name_L.png"
  shape="free"
  width={760}
/>

Select the name marked in red with the mouse, and copy it with **Ctrl + Shift + C**. Then open the leader launch file.

<Terminal where="Robot container">

```bash
sudo nano ~/ros2_ws/src/open_manipulator/open_manipulator_bringup/launch/omx_l_leader_ai.launch.py
```

</Terminal>

Set `port_name` to the leader serial path:

```python
# omx_l_leader_ai.launch.py
DeclareLaunchArgument(
    'port_name',
    default_value='/dev/serial/by-id/{your_leader_serial_id}',
    description='Port name for hardware connection.',
)
```

In nano:

1. Press **Ctrl + W**, type `port_name`, and press **Enter**. The line below it is the one to change.
2. Delete the old value between the quotes. Type `/dev/serial/by-id/`, then paste the name with **Ctrl + Shift + V**.
3. Save with **Ctrl + O**, then **Enter**. Close with **Ctrl + X**.

#### D. The follower's port

Unplug the leader's USB cable, and plug the follower's USB cable back in. **The follower's 12 V power must be on**, or the PC cannot see its board. Then check the OpenRB serial ID.

<Terminal where="Robot container">

```bash
ls -al /dev/serial/by-id/
```

</Terminal>

<TutorialMedia
  label="The terminal lists one board, the follower's. Its name is marked in red."
  src="/img/systems/omx/quick_start_guide/setup_guide/physical_ai_tools/setup_port_name_F.png"
  shape="free"
  width={760}
/>

Copy the name as in part C. Then open the follower launch file.

<Terminal where="Robot container">

```bash
sudo nano ~/ros2_ws/src/open_manipulator/open_manipulator_bringup/launch/omx_f_follower_ai.launch.py
```

</Terminal>

Set `port_name` to the follower serial path, in the same way as in part C:

```python
# omx_f_follower_ai.launch.py
DeclareLaunchArgument(
    'port_name',
    default_value='/dev/serial/by-id/{your_follower_serial_id}',
    description='Port name for hardware connection.',
)
```

Then plug the leader's USB cable back in. Type `exit` and press **Enter** to leave the robot container.

### You should see

When both launch files are updated, the port settings should look like this:

<TutorialMedia
  label="A launch file. The port_name part, marked in red, has /dev/serial/by-id/ followed by the board's name as its default_value."
  src="/img/systems/omx/quick_start_guide/setup_guide/physical_ai_tools/setup_port_name.png"
  shape="free"
  width={760}
/>

<Checks>

- Each file has the name of its own arm's board
- The two names are different

</Checks>

<NotGood>

| You see | Do this |
| --- | --- |
| `No such container` or `is not running` in part B | The download did not finish. Do part A again. |
| `./container.sh: No such file or directory` | Paste both lines of part B together. The first line goes to the right folder. |
| `No such file or directory` after `ls` | The PC sees no board. Push the USB cable in fully. For the follower, its 12 V power must be on too. |
| Two `OpenRB-150` names after `ls` | Both USB cables are in. Unplug the other arm's cable, then paste the `ls` line again. |
| `'open_manipulator' already exists` in part A | It was downloaded before. That is fine. |

</NotGood>

<details>
  <summary>How does it work?</summary>

  The robot software runs inside a Docker container named `open_manipulator`. A container holds a program together with everything that program needs. `./container.sh enter` opens a terminal inside it.

  Each arm talks to the PC through its OpenRB-150 board, and every board has its own name. Parts C and D write those names into the two files that start the leader and the follower, so the software always finds the right arm. The container shares the `open_manipulator` folder with your PC, so the change stays.

  Parts A to D are the steps of [ROS 2 Setup](./setup_guide/ros2_setup.mdx).

</details>

## 4. Move the leader arm \{#move-the-leader-arm}

Start the robot software and move the leader arm. The follower arm copies you.

<Caution>

- The follower moves by itself when the software starts. Keep its reach clear.
- To stop at any moment: **Ctrl + C** in Terminal 2, or pull the follower's 12 V plug.

</Caution>

### Do this

#### A. Fix the arms to the table

Use the clamps from the box, at the edge of the table.

<TutorialMedia label="A clamp fixes the base of an arm to the edge of the table" width={420} />

#### B. Start Zenoh

Enter the robot container again, as in [Install the software](#install-the-software).

<Terminal where="Terminal 1">

```bash
cd $HOME/open_manipulator/docker
./container.sh enter
```

</Terminal>

Then start Zenoh.

<Terminal where="Terminal 1">

```bash
zenohd
```

</Terminal>

<Terminal
  kind="output"
  where="Terminal 1"
  checks={{1: 'Leave it open'}}
  note="The long id at the end is different every time. That is fine."
>

```text
Started Zenoh router with id d6aa70c54ebfe25205e69d0f90b65924
```

</Terminal>

#### C. Start the arms

Open a second terminal with **Ctrl + Alt + T**, and enter the robot container there too.

<Terminal where="Terminal 2">

```bash
cd $HOME/open_manipulator/docker
./container.sh enter
```

</Terminal>

<Caution>

After you paste, the follower moves to its start pose for about 10 seconds. Then it goes at once to the shape the leader is in.

While it moves, **fold the leader into the same shape and hold it there.**

</Caution>

<TutorialMedia label="A hand holds the leader arm folded in the same shape as the follower arm's start pose" width={560} />

<Terminal where="Terminal 2">

```bash
ros2 launch open_manipulator_bringup omx_ai.launch.py
```

</Terminal>

#### D. Move the leader

Move it slowly. Squeeze the finger loop on its handle to close the gripper.

### You should see

<TutorialMedia
  label="A hand moves the leader arm, and the follower arm copies each move"
  src="/img/systems/omx/quick_start_guide/operation_guide/ai_teleop.gif"
  width={560}
/>

<Checks>

- The follower moved to its start pose by itself
- The follower copies the leader
- The gripper closes when you squeeze the finger loop

</Checks>

<NotGood>

| You see | Do this |
| --- | --- |
| `Unable to connect to a Zenoh router` in Terminal 2 | Terminal 1 is not running. Press **Ctrl + C** in Terminal 2, then do parts B and C. |
| `Error opening serial port!` | The PC cannot find an arm. Check both USB cables and the follower's 12 V power, as in [Connect OMX](#connect-omx). |
| `There is no status packet!` | Check the follower's 12 V power. If it is on, the arms may be swapped: do parts B to D of [Install the software](#install-the-software) again. |
| The follower reached its start pose but does not copy | Press **Ctrl + C** in Terminal 2. Check the leader's USB cable. Then do parts B to D of [Install the software](#install-the-software) again. |

</NotGood>

### Then stop

<Caution>

Lower the follower's gripper onto the table first. The follower goes limp when the software stops.

</Caution>

Press **Ctrl + C** in Terminal 2, then in Terminal 1. Lines with `ERROR` at the very end are normal.

<details>
  <summary>How does it work?</summary>

  The leader's arm motors are switched off, so your hand can move them. They only measure their angles, 100 times a second. The follower's motors go to the same angles right away. That is why the follower copies you, and why it jumps if the two arms start in different shapes.

  Zenoh lets the robot's programs talk to each other. For the commands behind this step, see [Teleoperation](./operation_guide/teleoperation.mdx).

  Both programs run inside the robot container, so you enter the container in each new terminal.

</details>
